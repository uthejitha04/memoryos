# Laptop Omi repair — 2026-09-08

Implemented the first three steps from the readiness audit for the laptop workflow.

- Localhost and Electron Connect Omi use the Python BLE client. Remote browser capture remains available separately.
- Audio frames follow Omi's documented notification counter and fragment index. Duplicate, missing, out-of-order, and wrapping counters are handled. PCM fragments are assembled before sample conversion; 8 kHz PCM is upsampled.
- One capture owner prevents concurrent tabs, microphones, and the pendant from mixing sessions. Invalid PCM input is rejected and releases the capture lock.
- The laptop client makes up to five reconnect attempts after a disconnect. Received audio is saved to WAV. Reconnect gaps are explicitly shown; audio produced while disconnected is not recovered from pendant storage.
- Browser streams stop with a warning when their server connection fails. This is not durable mobile buffering; native phone Omi capture and storage recovery remain future work.
- Session names cannot overwrite an existing recording when sessions start in quick succession.
- Final queued transcription is awaited before memory indexing. Background work is tracked, and database close is synchronized with database operations.
- Added the memory dependency to requirements, installed desktop dependencies, and cached the local MiniLM embedding, Whisper small, and distil-large-v3 polish models.
